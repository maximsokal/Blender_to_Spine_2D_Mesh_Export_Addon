# Testing and Release Validation

## Current candidate

The current extension candidate is **0.55.17**.

Supported target scope:

- Spine 4.2.43 remains the primary full target.
- Spine 4.1.24 is enabled only for `2-Axis Rotation + Scale` in single-object and standalone multi-object exports.
- Spine 4.1 connected, mixed, and 3-Axis requests remain fail-closed before Blender geometry work.
- Normal - UV Segments keeps `+Z` as the compatibility default until the public projection-direction UI slice.
- Typed single-object, standalone, connected, and mixed internal requests may use `ACTIVE_CAMERA` with Perspective or Orthographic cameras. The public export route remains standalone-only.
- Active Camera segmentation, decomposition, and strict triangulation complete in normalized world geometry before already-triangulated regions are projected into camera U/V/depth space.
- Source UV boundary ownership is validated immediately after world-transform normalization for signed-axis and Active Camera routes.
- `A1ProjectedObjectAnalysis` is the shared per-object origin, bounds, slot ownership, and nearest/farthest depth contract.
- Standalone, connected, and mixed Normal - UV Segments setup slots use complete far-to-near object blocks ordered by nearest evaluated vertex.
- Connected object mains remain anchor-relative under a global main placed at the selected anchor's absolute projected Object Origin.
- Connected hierarchy layers remain grouped by projected Object Origin depth independently from setup slot order.
- Mixed composition performs one final slot-only nearest-depth pass across connected and standalone subgroup boundaries.
- The 0.55.16 connected/mixed Blender acceptance oracle evaluates full Spine setup transforms with translation, rotation, scale, and `onlyTranslation` inheritance instead of rejecting valid local `+90/-90` wrapper rotations.
- Candidate 0.55.17 changes only the architecture contract around that shared oracle: the Active Camera worker owns the evaluator/model ID and the signed-axis worker reuses them through `shared`.
- Production Slice 5 placement, hierarchy, layers, draw order, mixed interleaving, rigs, constraints, attachments, UV topology, texture baking, and both Blender workers remain unchanged.
- Existing rendered Camera Projection, grouped camera overlay, and version codecs are unchanged.

A focused run is not a release gate. Every required validation layer must pass on one exact commit, and every runtime claim must use JSON generated by that commit.

## Validation layers

The repository uses five validation layers:

1. Blender-independent tests in `tests/`.
2. Real `bpy` tests in `tests_bpy/`.
3. Blender 5.2 headless integration scripts in `tests/blender_headless/`.
4. Exact Spine runtime probes for target-specific behavior.
5. Blender extension validation, isolated installation, and ZIP packaging.

The pure gate must prove:

- one immutable `A1ProjectedObjectAnalysis` per prepared object;
- projected Object Origin placement remains separate from nearest-vertex visual ordering;
- connected layers use projected Object Origin depth;
- connected setup slots use complete nearest-vertex object blocks;
- mixed composition performs one cross-subgroup slot-only pass;
- source-order and component-ID tie breaking remain deterministic;
- Active Camera connected/mixed preparation is allowed only for the internal Normal - UV Segments route;
- rendered Camera Projection does not enter the new object-block pass;
- the setup-transform evaluator composes translation, rotation, and scale;
- `onlyTranslation` inherits the parent-space origin but resets basis inheritance;
- the generated zero-X-scale, `onlyTranslation(+90)`, layer `-90`, object-main chain evaluates to the expected world origin;
- unsupported inheritance, non-zero shear, missing parents, duplicate names, and cycles fail closed;
- the Active Camera worker owns `_SETUP_TRANSFORM_MODEL` and the evaluator import;
- the signed-axis worker records `shared._SETUP_TRANSFORM_MODEL` and calls `shared._setup_world_position` without duplicating the model literal.

## Manual Spine gates

For Spine 4.1.24, import the exact JSON used by the runtime probes and verify standalone object visibility, independent controls, Scale reductions and enlargements, correct textures, and no connected wrapper.

For Spine 4.2.43, validate representative single, standalone, connected, and mixed exports. Cover all signed axes and Active Camera. Confirm camera-frame placement, setup world positions, contiguous object blocks, nearest-depth interleaving, object controls, textures, and unchanged setup pose.

## Release evidence

A release claim records:

- exact candidate commit SHA;
- clean working tree or exact local modifications;
- Python, Blender, Node, Spine Editor, and runtime versions;
- complete pytest summary;
- real-bpy summary;
- every required Blender-headless marker and report path;
- runtime oracle and scale-response reports;
- package build and isolated install results;
- final ZIP path, size, timestamp, and SHA-256;
- fresh manual Blender-to-Spine import results.

Do not state that a gate passed without its corresponding log. Do not reuse results from an older commit.

## Failure handling

When a test fails:

1. preserve the complete traceback;
2. identify the production owner, acceptance oracle, or stale contract;
3. fix the owning implementation rather than weakening an unrelated test;
4. rerun the focused failure;
5. rerun the complete affected layer;
6. rerun downstream Blender, runtime, and packaging gates when production behavior changed.
