# Troubleshooting

This document describes current **Spine2D Mesh Exporter 0.155.0** behavior.

## Use Analyze for diagnostics

Run **Analyze** when you want a current diagnostic report. Run it again after changing
selection, geometry, modifiers, UVs, seams, materials, images, renderer, camera, frame
settings, exact Spine project versions, or exporter settings.

Analyze is explicit and synchronous. It does not run in the background and it does not own
the Export button's enabled state. A stale or missing Analyze report does not by itself
prevent production Export.

Read the structured blocker/warning messages before trying to diagnose generated JSON
manually, but remember that Export independently performs its own real validation/preparation
and can still fail on an invalid request.

## Production Export fails

Common causes:

- the `.blend` file is not saved;
- no Mesh object is active/selected;
- the active source is not in Object Mode;
- output paths are invalid, colliding, or unwritable;
- required UV/material/image dependencies are missing;
- the active camera is missing for a camera-dependent mode;
- the target/profile/composition combination is unsupported;
- final topology cannot satisfy the attachment contract;
- depth/parallax settings exceed the allowed generated-surface contract.

Run Analyze to obtain preflight diagnostics when useful, then fix the underlying request and
export again.

## Object is in Edit Mode

The production preparation pipeline requires Object Mode and does not silently switch the
source mode.

Return to Object Mode, optionally rerun Analyze, and export again. This prevents ambiguous
ownership of edit-session BMesh data.

## Normal / UV output does not match modifier-shaped viewport geometry

Normal / UV Segments exports the original Mesh datablock topology. Geometry generated only
by active modifiers is not included automatically.

Analyze reports active ignored modifiers. Apply or convert the modifier when its generated
geometry must appear in Spine.

The exporter does not apply topology-changing modifiers automatically because source
vertex/loop/UV/region lineage must remain explicit.

## Missing source image

When source materials require an image dependency, repair the dependency before export.

Possible fixes:

- restore the file;
- correct the Blender image filepath;
- pack the image into the `.blend`;
- replace corrupt data;
- use **Generate If Missing** when generated fallback is valid;
- use **Force Generated** when source shading should intentionally be ignored.

## Missing or malformed UV layer

Required UV dependencies can come from explicit UV Map nodes, Texture Coordinate UV,
Attribute references, or active/render-active source roles.

Repair missing layer names, malformed coordinate buffers, invalid active roles, or shader
nodes that reference the wrong UV layer. Rerun Analyze afterward when you want updated
diagnostics.

## Material requires a rendered-camera representation

The exporter does not silently switch Export Mode.

If the material/representation cannot satisfy Normal / UV Segments, choose the explicit
Camera Projection or Depth Camera Projection mode that matches the intended output and
optionally rerun Analyze.

## Camera Projection or Depth Camera Projection fails

Confirm that:

- the Scene has a valid active camera;
- the camera is Perspective or Orthographic where required;
- the renderer/View Layer state is supported;
- the render can produce usable alpha coverage;
- projection alpha threshold is finite in `[0, 1]`;
- required World/lighting/reflection participation settings are valid.

The render transaction restores temporary camera/render/visibility changes. Restoration
failures are reported as errors, not ignored.

## Active Camera — Object Root Bone is stretched in setup pose

Current Object Root output must contain one generated `*_camera_setup` inverse child for
each active-camera depth group.

Expected hierarchy:

```text
<depth>_scale
-> <depth>
-> <depth>_camera_setup
-> generated vertex bone
```

Expected setup semantics:

- X/Y setup Transform rotations are neutral;
- depth Transform setup translation/scale are neutral;
- `<depth>_camera_setup.y` cancels the matching depth group's setup Y translation;
- the generated vertex bone stores the projected local X/Y position.

If a newly exported JSON has no `*_camera_setup` bones, or generated vertex bones are
parented directly to per-depth rotation bones, Blender may be running an older extension
build. Remove the installed extension, close Blender completely, install the current archive,
and export again.

Do not mix JSON generated by one extension build with textures or assumptions from another.

## Active Camera — Object Root pivot is wrong

Object Root must use the projected Blender Object Origin as `<prefix>_main` placement.

Check that you selected **Active Camera — Object Root Bone**, not Camera Root. Camera Root
intentionally uses camera-space zero as the main-bone pivot.

If the initial shape is correct but X/Y rotation happens around the wrong point, capture the
exported JSON and report the `<prefix>_main`, `<prefix>` base, active-camera depth groups,
and generated vertex parents.

## Active Camera — Camera Root placement is wrong

Camera Root must use one rigid camera-depth layer and place the projected Blender Object
Origin below that camera-relative hierarchy.

If the file contains many per-vertex camera depth groups, confirm the UI selection was
**Active Camera — Camera Root Bone** and not Object Root.

## Non-manifold or invalid topology

Final Normal attachments must satisfy the validated manifold-disk/topology contracts.

Repair:

- non-manifold edges;
- degenerate faces;
- invalid connectivity;
- unsupported loose geometry;
- topology that cannot be decomposed into valid final regions.

Custom seams do not bypass topology validation.

## Depth Camera Projection loses detail

Check:

- **Depth mesh error (px)** — lower values request denser sampling;
- **Max depth points** — increase when the requested topology legitimately needs more
  retained points;
- **Depth edge threshold** — very low values can disconnect candidate geometry;
- **Depth smoothing** — large values can reduce small depth variation.

The exporter fails instead of silently exceeding Max depth points.

## Positive parallax fails

A positive Parallax Horizon Angle increases retained union geometry. If the requested union
exceeds Max depth points, reduce the angle, increase Max depth points, or simplify the
source surface.

Also verify that virtual reserve views produce valid face-isolated camera coverage.

## Texture and Spine UV do not align

Do not mix output from different builds or export runs.

1. Remove/rename old JSON and textures.
2. Export again.
3. Confirm modification times changed.
4. Import the new JSON with its matching texture set.

Normal semantic bake writes image rows in the file-space orientation expected by exported
Spine UVs. Rendered-camera modes remap UVs into the final crop.

## Output path collision

Output namespace preflight uses conservative portable filename rules, including Windows
reserved-name/case-collision safety. This does not mean the extension is Windows-only.

Use distinct object/output names and avoid concurrent requests targeting the same finals.

## Stage or backup files remain

Transaction work files use names similar to:

```text
.spine2d-stage-*
.spine2d-backup-*
```

They are not Spine assets.

Depending on diagnostics preferences, failed stage data can be preserved intentionally.
Later export can recover stale work. Never delete work files owned by another running
Blender process.

## Existing output was replaced and export failed

The atomic transaction attempts to restore previous finals from backups. Inspect:

- the primary structured export error;
- cleanup diagnostics;
- remaining `.spine2d-backup-*` files;
- Blender system-console/file logs.

Keep the original export exception as the primary failure; cleanup errors are additional
diagnostics.

## GPU texture warning

A Blender GPU display warning does not by itself prove export success or failure.

Check the exporter result, staged texture validation, final committed files, and whether
Blender can reopen the saved image from disk.

## Useful logs

Open **Edit > Preferences > Extensions > Spine2D Mesh Exporter** and enable the appropriate
file/module logging.

For output problems, inspect infrastructure atomic/output modules. For material/bake
problems, inspect material, shader, semantic-bake, and camera-projection adapter modules.

## Disable or re-enable leaves stale behavior

The 0.155.0 lifecycle must remove owned classes, RNA, handlers, the Preferences one-shot
redraw timer, and manual-readiness UI method overrides when the extension is disabled.

If a development install behaves like an older build:

1. disable/remove it;
2. close Blender completely;
3. start Blender again;
4. install the exact current ZIP;
5. re-enable and verify the current version/metadata.

If duplicate panels/operators persist after a clean restart, capture the exact ZIP SHA256,
Blender version, and console traceback because that is a lifecycle regression.

## Bug report checklist

Include:

- extension version;
- exact commit SHA for a development build;
- Blender version and OS;
- selected Spine target and configured exact project version;
- Export Mode;
- Projection Direction for Normal / UV Segments;
- camera type for camera-dependent routes;
- Seam Maker/depth/parallax settings;
- source material policy;
- Analyze issue codes/messages when Analyze was run;
- Blender system-console traceback;
- whether the failure reproduces in a minimal copied `.blend`;
- whether source geometry, UVs, materials, camera, selection, frame, or render state changed
  unexpectedly;
- generated JSON and output filenames when they can be shared safely.

Do not publish private customer assets without authorization.
