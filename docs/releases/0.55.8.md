# 0.55.8

## Active Camera validation fixture correction

This candidate corrects the focused Slice 4 validation failures reported against
0.55.7. The production Active Camera projection, depth-parent compensation, standalone
draw-order planner, Blender adapter and headless acceptance worker are unchanged.

### Fixed

- The pure depth-compensation fixture now constructs the typed `LegacyZGroup` values
  required by `LegacyRigBuildRequest` instead of passing raw floats.
- The 0.55.7 release note now states explicitly that camera projection uses the export
  texture dimensions, matching the semantic release contract.
- Manifest, documentation and release-version contracts now identify candidate 0.55.8.

### Validation scope

- Rerun the focused Active Camera, signed-axis, Object Origin, documentation and release
  contracts before starting Blender acceptance.
- After focused tests pass, rerun both signed-axis Blender workers, the Perspective and
  Orthographic Active Camera worker, and the complete Python suite on the same commit.

### Unchanged

- No production projection or rig function changed in this correction.
- `+Z` remains the persisted compatibility default.
- The public UI still does not expose the projection dropdown.
- Connected and mixed Active Camera requests remain fail-closed until Slice 5.
