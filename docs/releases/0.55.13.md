# 0.55.13

## Active Camera acceptance depth numeric correction

The 0.55.12 Blender acceptance reached the corrected pre-projection triangulation path and then exposed a numeric mismatch in the worker's expected camera depth. Production calculated depth from captured Blender matrix and vertex values using Python affine arithmetic, while the worker used `mathutils` matrix-vector multiplication with float32 intermediates. The observed delta was approximately `2.23e-7`.

### Fixed

- The Active Camera Blender worker now captures source vertices, object matrices and the scale-independent camera view matrix as Python tuples.
- Expected world positions and camera-local Z are calculated with explicit Python affine arithmetic.
- The JSON report records `depthExpectationModel = CAPTURED_TUPLE_AFFINE` and the retained depth tolerance.
- A Blender-independent AST contract prevents the depth oracle from returning to `matrix @ Vector` arithmetic.

### Preserved

- Blender `world_to_camera_view` remains the independent oracle for screen X/Y coordinates.
- `_DEPTH_TOLERANCE` remains `1e-8`; it was not weakened to hide float32 disagreement.
- Production Active Camera projection, pre-projection triangulation, depth compensation, rig assembly, standalone draw order, signed-axis projection, rendered Camera Projection, connected and mixed assembly, Spine codecs, UV topology and texture baking are unchanged.
