# 0.55.5

## Projection slice contract and documentation correction

The signed-axis production projection and Blender 5.2 acceptance behavior are unchanged.

The complete Python suite exposed two stale contracts after the 0.55.4 Blender acceptance passed:

- `test_appended_settings_preserve_uv_policy_and_rig_positional_order` still treated the
  pre-projection six-field dataclass suffix as permanent and did not include the appended
  `projection_direction` field;
- the public documentation index and related release guides still identified an older
  extension version instead of matching `blender_manifest.toml`.

The corrected candidate now:

- verifies the final seven appended `A1SingleObjectExportSettings` fields in their exact
  compatibility-preserving order;
- keeps `projection_direction` after `rig_setup_pose_mode`, so all older positional fields
  remain unchanged;
- synchronizes the manifest version across `docs/README.md`, `docs/CHANGELOG.md`,
  `docs/installation.md`, and `docs/testing.md`;
- records `0.55.5` as the current candidate and expected package name;
- retains `+Z` as the default Normal - UV Segments projection until the later public UI
  slice is implemented.

No geometry, UV, rig, JSON, Camera Projection, standalone, connected, mixed, or Spine codec
production code changed in this correction.
