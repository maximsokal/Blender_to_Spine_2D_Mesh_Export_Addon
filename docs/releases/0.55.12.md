# 0.55.12

## Active Camera perspective n-gon triangulation correction

Blender 5.2 headless validation exposed a production ordering defect in Normal - UV Segments `ACTIVE_CAMERA` preparation. The previous pipeline projected a valid planar Blender polygon into retained `(screen U, screen V, camera-local depth)` coordinates before running the strict geometry triangulator. Perspective projection is nonlinear in that three-dimensional representation, so a planar source quad could become non-planar after projection and fail the unchanged `1e-6` planarity contract.

### Fixed

- Active Camera segmentation, decomposition and strict triangulation now complete in normalized world geometry before any camera projection.
- Only the already-triangulated immutable region snapshots are projected into camera screen and depth space.
- The projected source snapshot remains authoritative for Object Origin placement, Z-group assignment, nearest-vertex draw order and final attachment coordinates.
- A pure tilted-quad regression proves that direct post-projection triangulation reproduces the non-planarity failure while pre-projection triangulation produces two valid projected triangles with unchanged Source lineage.
- Production diagnostics record `active_camera_preprojection_triangulation=1` for the corrected route.

### Unchanged

- The strict general polygon planarity tolerance remains `1e-6`; it was not weakened.
- Signed-axis projection, standalone object-block ordering, existing rendered Camera Projection, connected and mixed assembly, Spine codecs, UV lineage and texture baking remain unchanged.
- The public projection dropdown is still deferred to the later UI slice.
