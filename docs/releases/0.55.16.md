# 0.55.16

## Connected setup-transform acceptance correction

The 0.55.15 Blender gate reached the six-axis connected/mixed worker after all existing single-object and standalone projection workers passed. The worker then rejected the generated two-axis connected hierarchy because it assumed every bone in the object-main parent chain must have zero local rotation.

That assumption was incorrect. The production two-axis Z wrapper intentionally contains a `+90` degree scale-layer bone using `onlyTranslation` inheritance followed by a `-90` degree layer bone. Their evaluated setup basis is neutral even though the individual local rotations are not zero. The production hierarchy was therefore valid; the acceptance oracle was incomplete.

### Fixed

- Added a Blender-independent Spine 2D affine setup evaluator for acceptance workers.
- The evaluator composes local translation, rotation, and scale through the complete parent chain.
- `normal` and `onlyTranslation` inheritance are supported explicitly.
- Duplicate bones, missing parents, parent cycles, conflicting inheritance aliases, unsupported inheritance modes, and non-zero shear fail closed.
- Signed-axis and Active Camera connected/mixed workers now evaluate object-main world positions with the same shared setup-transform oracle.
- Worker reports identify the model as `SPINE_AFFINE_NORMAL_ONLY_TRANSLATION`.
- Pure regressions reproduce the exact connected chain containing zero helper X-scale, `onlyTranslation(+90)`, `layer(-90)`, and the compensated object-main translation.

### Unchanged

- Production Slice 5 placement, hierarchy, projected-object analysis, origin-depth layers, nearest-vertex draw order, mixed subgroup interleaving, rigs, constraints, attachments, UV topology, and texture baking are unchanged.
- Existing rendered Camera Projection, grouped camera overlay, public standalone-only UI routing, and Spine codecs are unchanged.
- Spine 4.1 connected and mixed capability restrictions remain fail-closed.
