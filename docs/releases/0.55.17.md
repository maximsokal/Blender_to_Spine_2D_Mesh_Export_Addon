# 0.55.17

## Route-aware setup-model architecture contract correction

The 0.55.16 focused validation proved the affine setup evaluator itself but exposed one stale architecture assertion. The assertion required the canonical setup-model string literal to appear physically in both connected/mixed Blender workers even though the signed-axis worker intentionally reuses the Active Camera worker as the shared oracle owner.

### Fixed

- The connected/mixed worker architecture contract now distinguishes the shared owner from the shared consumer.
- The Active Camera worker must import `evaluate_spine_setup_bone_position`, own `_SETUP_TRANSFORM_MODEL = "SPINE_AFFINE_NORMAL_ONLY_TRANSLATION"`, and write that value into its report.
- The signed-axis worker must call `shared._setup_world_position` and write `shared._SETUP_TRANSFORM_MODEL` into its report without duplicating the string literal.
- The contract continues to reject the obsolete translation-only setup helper.

### Unchanged

- The Blender acceptance workers and `spine_setup_transform.py` are unchanged from 0.55.16.
- Production Slice 5 placement, hierarchy, depth layers, nearest-vertex draw order, mixed interleaving, rigs, constraints, attachments, UV topology, texture baking, rendered Camera Projection, and public UI routing are unchanged.
- Spine 4.1 connected and mixed restrictions remain fail-closed.
