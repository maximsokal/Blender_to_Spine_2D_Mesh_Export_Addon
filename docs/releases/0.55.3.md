# 0.55.3

## Blender axis-projection acceptance numeric correction

The signed-axis production projection introduced in `0.55.2` is unchanged.

The Blender 5.2 headless acceptance worker previously calculated expected transformed
vertices through `mathutils.Matrix @ Vector`. Blender stores and evaluates those
intermediate values with float32 precision, while the production snapshot normalizer
reads the evaluated Mesh and matrix values into Python and performs the linear transform
with Python float arithmetic.

For the acceptance fixture this produced a harmless difference of approximately
`2.38418579e-7`, which exceeded the worker's former absolute tolerance of `1e-7` even
though the selected axis, sign, Object Origin and geometry were correct.

The corrected worker now:

- captures the evaluated Blender matrix and Mesh vertex coordinates once;
- independently applies the same documented affine linear formula using those captured
  values;
- projects the expected normalized vectors through the approved signed-axis basis;
- keeps a strict `1e-10` integration tolerance instead of hiding the mismatch by broadly
  relaxing comparisons;
- records maximum vertex, Object Origin and main-bone deltas for every direction;
- continues to verify source matrix and Mesh immutability exactly.

This release changes acceptance synchronization and diagnostics only. Production axis
projection, UV processing, Spine rigs, Camera Projection, standalone composition,
connected composition and Spine codecs are unchanged.
