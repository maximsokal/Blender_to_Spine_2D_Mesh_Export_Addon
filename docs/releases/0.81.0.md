# Release 0.81.0

## Scope

Version 0.81.0 adds a third public export mode: **Depth Camera Projection**. The two
established modes remain unchanged:

```text
Normal / UV Segments
Camera Projection
Depth Camera Projection
```

Depth Camera Projection renders the source through the active Blender camera like flat
Camera Projection, but replaces the flat contour attachment with an optimized visible
depth-relief surface. Retained depth points receive the existing Normal / UV Segments
generated vertex-bone treatment, so the object keeps pseudo-three-dimensional internal
form when its Spine controls are animated.

The mode does not export Blender camera animation and does not require a new user-facing
rig selector.

## Camera space and relief base

The active camera is the single depth zero for every exported object. Blender camera-local
Z remains available in diagnostics, where visible points are negative. Generated rig
geometry converts that value to positive camera distance:

```text
camera plane                     = 0
nearer visible point distance    > 0
farther visible point distance   > nearer distance
```

This shared zero is not reset independently for every object. Consequently, two objects
at different camera distances retain different, non-overlapping depth ranges in one
multi-object Spine document.

The public local relief policy is **Farthest Visible Point**:

- the farthest visible point is the back surface of that object's one-sided relief;
- all other retained points lie between that back surface and the camera;
- no generated point may extend farther from the camera than the selected back surface;
- the local relief policy never replaces the shared camera zero used by the rig;
- projected Blender Object Origin X/Y is retained for each standalone object.

`Object Origin` is implemented as a hidden fail-closed relief-base policy for future use.
It is accepted only when Object Origin lies behind every visible point. The 0.81.0 UI
exposes and uses only Farthest Visible Point.

## Depth surface

The evaluated dependency-graph mesh is triangulated and projected through the active
Perspective or Orthographic camera. The exporter samples only the front-most visible
surface on a bounded screen lattice and creates a new generated MeshSnapshot rather than
copying every Blender vertex.

Depth discontinuity filtering is topology-aware. A steep continuous source face is not
mistaken for a foreground/background gap merely because adjacent camera distances differ
by more than the user threshold. Unrelated overlapping surfaces still remain disconnected.

## Optimization controls

Depth Camera Projection adds four public controls:

- **Depth Smoothing** — edge-aware blending strength for neighboring depth samples;
- **Depth Edge Threshold** — maximum neighboring depth jump, expressed as a fraction of
  the visible object depth range;
- **Depth Mesh Error (px)** — requested screen-space sample spacing;
- **Max Depth Points** — hard limit for retained points and their generated bones.

Smoothing never crosses a protected depth discontinuity. When the selected point limit or
active-camera projection cannot produce a valid two-dimensional relief surface,
readiness/export fails with a structured diagnostic instead of silently flattening or
creating unbounded geometry.

## One attachment per depth object

A generated Depth Camera Projection surface is already the final optimized screen-space
mesh. It is not passed through the Normal / UV Segments disk-region serializer. Every
depth object therefore produces exactly one visual slot and one weighted mesh attachment:

```text
<object>_Segment_0
```

Disconnected visible islands may remain disconnected inside that one attachment. The
exporter does not create a stray `<object>_Segment_1` for a small residual triangle.

Every retained depth point owns one generated vertex bone. The vertex bone's local Y
subtracts its parent depth-group setup offset, so the reconstructed Spine setup position
is exactly the projected screen point:

```text
vertex_local_y + parent_depth_y = projected_screen_y
```

This prevents camera depth from being applied twice in the Spine setup pose.

## Texture and crop pipeline

Depth Camera Projection combines established production boundaries:

- active-camera render, alpha coverage, crop, and scene influence from Camera Projection;
- generated weighted vertex bones and rig controls from Normal / UV Segments;
- direct full-frame camera UV authored by the generated depth surface;
- post-render conversion to crop-local UV without changing weighted vertices, triangles,
  hull, or bone indices.

The source Mesh, source UV layers, materials, transforms, active camera, render settings,
selection, active object, current frame, and temporary Blender datablocks remain protected
by transactional state guards.

## Sequence behavior

A Depth Camera Projection sequence advances the Blender timeline only to evaluate animated
materials, image nodes, and their dependencies. It must not bake Blender object movement,
object rotation, active-camera movement, or active-camera lens animation into the PNG
sequence.

For the sequence owner, the exporter creates temporary setup-pose render proxies:

- an evaluated source-mesh proxy with fixed geometry and fixed `matrix_world`;
- an active-camera proxy with fixed transform and fixed camera data;
- original source and camera animation remain untouched;
- all proxy Objects, Meshes, and Camera datablocks are removed in `finally`.

Therefore sequence frames may change visible RGB because the material changed, while the
alpha silhouette and render crop remain identical. Flat `Camera Projection` keeps its
established timeline behavior and does not use these Depth-specific proxies.

Per-object sequence timing remains independent:

```text
Object A: Frames = 2  → two-frame material sequence
Object B: Frames = 0  → one static texture
```

The combined JSON assigns native sequence metadata and a sequence timeline only to the
sequence owner. Static siblings remain static. Texture namespaces and atomic output
reservations remain separate for every object.

Connected and mixed composition remain limited by the existing target/profile capability
registry. Version 0.81.0 does not broaden those public capability claims.

## Validation matrix

The Blender 5.2 acceptance includes:

- Perspective Depth Camera Projection for Spine 3.8, 4.0, 4.1, 4.2, and 4.3;
- Orthographic Depth Camera Projection for Spine 4.2;
- a two-frame Spine 4.2 Depth Camera Projection material sequence;
- a public Spine 4.2 standalone multi-object export with one sequence depth object and
  one static depth object;
- animated source transforms and animated active-camera transform/lens in the multi-object
  fixture, while sequence silhouette and crop must remain fixed;
- distinct projected main-bone positions and distinct positive camera-distance ranges;
- exactly one weighted attachment per depth object and no generated Segment 1;
- physical PNG validation, crop-local UV, weighted vertices, generated vertex bones,
  target-specific bone/constraint schema, triangle preservation, sequence ownership,
  and Blender-state restoration;
- Blender-independent interpolation, front-most visibility, topology-aware edge filtering,
  point budget, camera-distance conversion, parent-offset compensation, schema, UI, and
  routing contracts.

## Compatibility

- Blender minimum: 5.2.0.
- Scene settings schema: 7.
- Existing `Normal / UV Segments` behavior is unchanged.
- Existing flat `Camera Projection` behavior is unchanged.
- Existing saved Scenes are migrated without changing their selected export mode.
- Spine JSON target selection remains 3.8.99, 4.0.64, 4.1.24, 4.2.43, or 4.3.23.
