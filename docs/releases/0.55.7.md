# 0.55.7

## Normal / UV Segments Active Camera projection

This candidate implements Slice 4 of the approved projection-space plan without exposing
the later public projection dropdown.

### Added

- A Blender-independent evaluated-camera frame for Perspective and Orthographic cameras.
- Full world-vertex and Blender Object Origin projection into centred export-texture pixels.
- Camera-local depth preservation for per-vertex depth groups and nearest-vertex draw order.
- Explicit compensation for the existing object-bake attachment Y conversion, avoiding a second attachment pipeline.
- Pure tests for Perspective, Orthographic, export-canvas dimensions, near-plane rejection, out-of-frame geometry, Object Origin placement and nearest-vertex depth.
- Blender 5.2 headless acceptance against Blender camera-view coordinates for single-object preparation and standalone object-block composition.

### Changed

- Typed `ACTIVE_CAMERA` Normal / UV Segments requests use the active evaluated Scene camera while retaining ordinary UV segmentation, object baking, separate textures, independent rigs and existing controls.
- Standalone Active Camera setup slots use the shared far-to-near complete object-block planner from 0.55.6.
- Camera screen coordinates use `texture_width` and `texture_height`; Scene render resolution, resolution percentage and pixel aspect are not used as the projection canvas.

### Fail-closed scope

- Missing Scene camera, unsupported camera types, invalid matrices, Object Origins or vertices on/behind the near plane, and mixed projection directions are blocking errors.
- Connected and mixed Active Camera requests remain blocked until Slice 5 supplies camera-relative hierarchy and placement normalization.

### Unchanged

- `+Z` remains the persisted compatibility default.
- The public UI does not yet expose the projection dropdown.
- Existing rendered Camera Projection, camera crop/contour logic, grouped camera flattening, connected assembly, mixed assembly, Spine codecs, UV topology, texture formats and animation namespaces are unchanged.
